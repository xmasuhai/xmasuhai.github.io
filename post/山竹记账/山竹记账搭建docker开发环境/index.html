1. 环境 ⇧

环境主要分两种：生产环境 和 开发环境 兼容 Windows 11、macOS、Linux

生产环境 ⇧

  • 一般使用 Linux 服务器（包括买云服务器）
  • 关闭 debug 端口
  • 使用 log 日志进行排错
  • 环境变量 举例：RAILS_ENV=production
  • 编辑器： vi 或 vim 或 neovim
  • Shell：bash 或者 sh

开发环境 ⇧

  • 一般使用 Windows 或者 macOS
  • 开启 debug 端口
  • 使用 log 或者断点进行排错
  • 环境变量 一般不设置，默认：development
  • 编辑器： VSCode（直连Docker） 或 JetBrains（无法直连Docker）
  • Shell：zsh 或者 fish

生产环境 与 开发环境 系统不一致导致的 bug ⇧

  • 缺少依赖库
  • API不兼容

为了减少环境不一致带来的bug，确保每个开发运维人员生产环境和开发环境一致，需要使用 Docker，保证环境一致

Docker 优缺点对比 ⇧

优点：

  • 在所有地方（操作系统）使用同一套环境
    • 在 Windows 里运行 Linux 容器，开启 WSL2
    • 在 macOS 里运行 Linux 容器
    • 在 Linux 里运行 Linux 容器

缺点：

  • 学习门槛较高
    • 需要会 Linux 命令
    • 需要了解容器的概念
    • 需要做端口映射
    • 需要做数据卷映射
  • 占用内存和硬盘

3. 使用Docker的准备工作 ⇧

各个操作系统的基本要求

  • Win11 开启 WSL
  • macOS 版本 10.15+，不可安装 VirtualBox
  • Linux 内核 3.10+

win11 开启 WSL2 ⇧

  1. 控制面板\所有控制面板项\程序和功能 点击 启用或关闭Windows功能，勾选 Hyper-V、Windows拟机监控程序平台、适用于Linux的Windows子系统，确认并重启
  2. 家庭版开启 Hyper-V 需额外设置
  3. Windows 11 安装 WSL2，启动终端或打开Power Shell 以管理员命令输入下方代码： bcdedit /set hypervisorlaunchtype auto
  4. 使用 PowerShell，以管理员权限启动，输入下方命令执行：wsl --install -d Ubuntu，需要重启计算机
  5. 系统登录，设置默认账户和密码，该账户默认为该Linux系统的管理员，具备和root相同的权限。（root已经有了不能起重复的账户名）
  6. 升级WSL内核：wsl --update
  7. 重启WSL内核：wsl -l -shutdown
  8. 查看本系统WSL情况：wsl -l -v
  9. 在Ubuntu命令行中，升级Linux系统的包：sudo apt update && sudo apt upgrade
  10. 查看可用发行版列表：wsl --list --online / wsl -l -o
  11. 更改默认安装的 Linux 发行版：wsl --install -d <Distribution Name>
  12. 如果要通过 Linux/Bash 命令行（而不是通过 PowerShell 或命令提示符）安装其他发行版，必须在命令中使用 .exe：wsl.exe --install -d <Distribution Name> 或若要列出可用发行版，则使用：wsl.exe -l -o
  13. 使用 wsl --install 命令安装的新 Linux 安装将默认设置为 WSL 2，无需额外设置：wsl --set-default-version 2
  14. 在终端启动运行，ubuntu.exe 或 ubuntu 或 wsl.exe
  15. 查看当前目录路径在 WSL 中的装载位置：wsl pwd
  16. 如果已在 Windows 提示符或 PowerShell 窗口中打开 WSL 命令行并想退出，请输入命令：exit

4. oh-my-env 环境说明 ⇧

oh-my-env 工作空间 ⇧

  • oh-my-env 会自动映射为 workspaces/oh-my-env
    • 该目录里的文件是本地系统和容器 内外共享 的
    • ntfs 系统格式，性能一般
    • temp 目录可作为文件中转，实时更新，有时需要手动点击刷新
  • 提前另外准备好了 ~/repos 目录，该目录是 容器专属 的，性能较好
    • 默认会在 ~/repos 中工作，存放各个项目代码
    • 需要共享时才会用到 workspaces/oh-my-env/temp 目录
    • cd ~/repos 或者 cd root/repos
    • 在 docker deskop 的数据卷中可以查看

oh-my-env 持久化 ⇧

  • 在 Ctrl + Shift + P 弹出框内输入 rebuild container 相当于 重装Linux系统
  • 重新构建镜像后，未持久化的目录都会被删除
  • 只有写在 mounts 配置中的目录和 oh-my-env 目录（容器外系统可访问）会被保留
    • 会被持久化到数据卷中，不会随容器重启或重建而消失

现有功能

  • archlinux
  • zsh 已配置终端，相当于 bash
  • fzf 索引当前目录下所有文件，可模糊查找，只可以找到文件目录路径，该命令无法打开
    • 使用自定义脚本，操作打开目录或者文件 vi ~/.bashrc
    • 命令 fd 打开文件所在的目录
    • 命令 f 使用默认的 editor 打开文件
    • 命令 j 会用 fzf 打开所有打开过的目录，可快速查找，回车可进入该目录
    • 命令 jj 反悔重新查找
  • rvm + ruby + gem + bundle
  • nvm + node + pnpm
  • go
  • git
  • vscode
  • 各种国内加速
  • 其他多余的已删除
    • neovim
  • docker in docker(dockerd)
    • 使用命令 dockerd 来启动
    • 新打开一个终端，输入 docker ps 查看运行的镜像
    • 可运行 docker run hello-world 成功显示 Hello from Docker!
    • chezmoi 可管理所有配置

如何自定义

  • 打开 .devcontainer/Dockerfile
  • 使用 RUN 命令来添加想要的依赖，方便扩展，例如：
    • RUN yes | pacman -S fish
    • RUN npm i -g http-server
    • 然后 rebuild container 即可
  • 更多功能可查看 oh-my-docker
    • oh-my-env-1
    • oh-my-docker-m1
    • 新 oh-my-rust-env
    • 旧 oh-my-docker-for-rust

7.高性能文件： docker volume ⇧

在容器项目中运行 mkdir aaa;touch aaa/frank.txt

  • 发现需要手动刷新 VSCode 目录才能看到添加的文件/文件夹
  • docker 没有立即检测到文件变化

加速方法

  • 在docker desktop > Volumes中，新建一个 Docker volume，自定义命名
  • 相当于在命令行运行 docker volume create xxx

  • 在my-projects/.devcontainer/devcontainer.json 中改写 mounts 为

}

  • 在 VSCode 中运行 rebuild Container

  • 这样一来 high_speed_files 目录里的文件的性能就非常高了，名称可以任意

8.连接任意数据库 ⇧

连接 MYSQL 步骤

  1. 创建 network1
  2. 启动 mysql1 server 容器服务，连入 network1
  3. 让 oh-my-docker 连入 network1
  4. 预装 mysql 客户端镜像
  5. 重启重新构建容器 rebuild
  6. 验证连接 mysql -u root -h mysql1 -p

创建 network1 ⇧

  • 打开 windows 终端（非容器内），运行命令 docker network create network1
  • 相当于组建了一个局域网 wifi，需要将mysql服务器和 docker连入该wifi
  • 如果报错，就换一个网络名称 network2

启动 mysql 镜像，得到数据库服务的容器 ⇧

  • 搜索 docker hub mysql
    • mysql docker
    • windows终端中运行 docker run --name mysql1 -e MYSQL_ROOT_PASSWORD=123456 --network=network1 -d mysql:5.7.35
    • 说明：docker run --name 数据库名称 -e MYSQL_ROOT_PASSWORD=数据库密码 --network=需要连入的网络 -d mysql:数据库版本号
    • -d 表示 deamon

9.常用的 docker 命令一览表 ⇧

  • docker ps 查看正在运行的容器
  • docker ps -a 查看运行过的容器
  • docker pull ubuntu:20.04 下载 ubuntu 镜像
  • docker pull myregistry.local:5000/testing/test-image:0.1 下载指定域名下的镜像
  • docker run --name test -dit alpine 由镜像得到容器（容器在后台运行），并把容器取名为 test
  • docker run alpine sh 由镜像得到容器，并运行 sh 命令（容器在当前终端运行）
  • docker run -p 9090:8080 -dit alpine 端口映射
  • docker run -e ENV1=foo -dit alpine 设置环境变量
  • docker run --network=xxx -dit alpine 设置网络
  • docker stop container_id 或 docker kill container_id 停止容器（二者区别见这里）
  • docker start container_id 开始运行容器
  • docker rm container_id 删除已停止运行的容器
  • docker rm -f container_id 强制删除容器，不管有没有在运行
  • docker rm $(docker ps --filter status=exited -q) 删除所有已停止运行的容器
  • docker rmi image_id 删除镜像
  • docker system prune 删除占用硬盘的垃圾对象，包括没用的 container、images、network
  • docker image prune -a 删除所有没被用到的镜像

#!/bin/bash

# 定义源路径和目标路径
BACKUP_DIR="/workspaces/oh-my-env-2/temp/dotEnv_backup"
SRC_DIR="/root"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
ZIP_FILE="${BACKUP_DIR}/backup_${TIMESTAMP}.zip"

# 创建备份目录（如果不存在）
mkdir -p "${BACKUP_DIR}"

# 创建一个临时目录用于收集备份文件
TEMP_STAGE=$(mktemp -d)

echo "开始复制备份文件..."

# 复制 bash_modules 文件夹
if [ -d "${SRC_DIR}/bash_modules" ]; then
    cp -r "${SRC_DIR}/bash_modules" "${TEMP_STAGE}/"
    echo "✔ 已复制 bash_modules"
else
    echo "⚠ 未找到 ${SRC_DIR}/bash_modules"
fi

# 复制 .ssh 文件夹
if [ -d "${SRC_DIR}/.ssh" ]; then
    cp -r "${SRC_DIR}/.ssh" "${TEMP_STAGE}/"
    echo "✔ 已复制 .ssh"
else
    echo "⚠ 未找到 ${SRC_DIR}/.ssh"
fi

# 复制 .bashrc 文件
if [ -f "${SRC_DIR}/.bashrc" ]; then
    cp "${SRC_DIR}/.bashrc" "${TEMP_STAGE}/"
    echo "✔ 已复制 .bashrc"
else
    echo "⚠ 未找到 ${SRC_DIR}/.bashrc"
fi

# 检查临时目录中是否有文件
if [ "$(ls -A ${TEMP_STAGE})" ]; then
    echo "开始压缩为 zip..."
    # 切换到临时目录压缩，避免包含绝对路径层级
    (cd "${TEMP_STAGE}" && zip -r "${ZIP_FILE}" .)
    
    if [ $? -eq 0 ]; then
        echo "稳定备份成功！文件已保存至: ${ZIP_FILE}"
    else
        echo "❌ 压缩失败！"
    fi
else
    echo "❌ 没有找到任何需要备份的文件或文件夹。"
fi

# 清理临时目录
rm -rf "${TEMP_STAGE}"
  • 即使删除镜像，仍可还原配置文件
