sequenceDiagram
    autonumber
    actor U as 用户
    participant B as 浏览器（App）
    participant S as 服务器（Rails）
    participant D as 数据库（PostgresSql）
    participant M as 用户邮箱

    U->>B: 输入邮箱 / 点击发送验证码
    B->>S: 请求创建验证码
    S->>D: 验证成功 / 请求数据库生成验证码
    D-->>S: return email / ValidationCode
    S-->>M: 发送证码到用户邮箱

    U-->>M: 打开邮箱查看
    M-->>U: 返回（邮箱中收到验证码）
    U->>B: 输入验证码 / 点击登录

    B->>S: 请求登录
    S->>D: 验证 email / ValidationCode
    D-->>S: return
    S-->>B: 通过或失败
    B-->>U: 登录成功或失败

    # spec/support/rspec_api_documentation.rb
# 修复 rspec_api_documentation 与 Rack 3 / rack-test 2.2 的兼容问题。
#
# 现象：Rack 3 / rack-test 2.2 在 GET 等无请求体的请求中，不会向 env
# 中写入 `rack.input`，导致 `last_request.env["rack.input"]` 为 nil。
# rspec_api_documentation 6.1.0 的 ClientBase#read_request_body 会直接对其
# 调用 `rewind`，抛出：
#   NoMethodError: undefined method `rewind' for nil:NilClass
#   input.rewind
#
# 处理：当 rack.input 为 nil 时返回空字符串，避免对 nil 调用 rewind；
# 非 nil 时保持原有 rewind + read 行为。
module RspecApiDocumentation
class ClientBase
def read_request_body
  input = last_request.env["rack.input"]
  return "" if input.nil?

  input.rewind
  input.read
end
end
end

class Api::V1::ValidationCodesController < ApplicationController
  def create
    code = SecureRandom.random_number.to_s[2..7]
    validation_code = ValidationCode.new email: params[:email],

有个逻辑问题 ⇧

  • api文档不应该展示错误，只需要显示正确请求的文档
  • 422 Unprocessable Content 是不必要的
  • 目录名称 acceptance 也说明了这一点，只放后端接受前端发的请求
  • 如果不接受，最好放到其他目录测试，比如 spec/requests 中

回顾 ⇧

  • 为了是文档中请求 Header有 Content-Type字段，需要在每一次单独请求的时候添加 header "Content-Type", "application/json"
    • 后续可优化
  • 为了让请求Body展示json，需要在 spec/rails_helper.rb 添加配置 config.request_body_formatter = :json
  • 为了让响应Body展示json，需要在 Gemfile 中引用魔改过的版本 gem "rspec_api_documentation", path: "./vendor/rspec_api_documentation"

class Api::V1::ValidationCodesController < ApplicationController
  def create
    code = SecureRandom.random_number.to_s[2..7]
